The problem

Give a 3B‑parameter model the firewall, and 30 of 100 commands break policy.

Llama‑3.2‑3B, running locally, receives a flow and a written operator policy, then calls allow, block or rate_limit. The prompt says the rules. The model breaks them anyway — under conflicting goals, and under injected instructions.

02 / 06
Architecture

Separate who suggests from who decides.

01 · TrustedFlow classifier

Random Forest on ISCXVPN2016 labels each flow: p2p, streaming, VoIP…

02 · UntrustedLLM agent

Reads scenario, emits one JSON tool call. Never executes anything.

03 · DeterministicPolicy gate

Dispatch → schema → flow identity → rules P1–P3. No LLM inside. Pure lookup.

04 · EffectNetwork

Only permitted actions reach the simulator.

P1 p2p → block only · P2 streaming / file transfer → block or ≤ 1024 kbps · P3 everything else → any action ≤ 10 000 kbps

05 / 06
What remains

The gate is only as honest as the labels it trusts.

All 6 surviving violations trace to classifier mislabels. Give the gate perfect labels (oracle) and violations fall to 0.

Safety moved from the model's judgement to a 3‑microsecond lookup — and the remaining risk now has a name and an address.
